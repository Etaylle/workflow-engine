## How to test (owner)

**Start** (from the project folder): `ci/run env-up` builds the frontend and the jar, starts PostgreSQL if needed and the engine at **http://localhost:8080**. Stop it with `ci/run env-down`. All checks: `ci/run all-local`.

**With the stub, no key, no cost**: `ENGINE_AI_STUB=true ci/run env-up`. Every Claude answer is then the canteen example (any text you type gives the same brief, 3 questions, 5 requirements and a 6-step workflow); type any text as the key (for example `sk-test`).

**With a real key**: `ci/run env-up` (no `ENGINE_AI_STUB`). Click **AI key** in the header (every screen). Two slots, memory only, gone after an engine restart:
- *Gemini (free tier)*: leave the provider on "Google Gemini", paste the key into "Gemini API key" (Google AI Studio, aistudio.google.com/apikey), "Test" (one tiny call with the base URL and model shown, `gemini-flash-lite-latest`; the provider's own error text appears when it fails), "Save". The header then reads "AI key: Gemini (…1234)" and the project page "AI for planning: Gemini · gemini-flash-lite-latest". Then run the click path below. A 429 says how many seconds to wait.
- *Anthropic*: the "Anthropic API key" slot (or the field of the new-project form); planning uses `claude-sonnet-5-5`, and building needs this key (or `ENGINE_EXECUTION_USE_SIGN_IN=true`).
- With both keys set, "AI for planning" picks the provider. OpenAI, Groq, OpenRouter and Custom are presets of the second slot; base URL and model can be edited. Calls can take up to five minutes each.

**Click path** (the page is `/`; the open project is in the address after `#`, the list is `#projects`, so a reload keeps your place):

0. The start page is "All projects" (open, rename, delete with confirmation). "New project" opens "Describe your idea" (address `#new`).
1. Type the optional name, the wish and the key ("Test" checks the key), "Send to the AI".
2. "Research and ask questions": Claude writes the brief and at most 8 questions; the AI's proposal is preselected on each. Edit, delete or add single questions ("Add a question", "Ask again" replaces all), change answers that do not fit, "Save answers".
3. "Write the requirements with Claude": requirements grouped by epic.
4. "Write the workflow with Claude": swimlane diagram. "Write it again" replaces it.
5. "Review and confirm" shows the counts; "Confirm as contract" freezes wish, brief, answers, requirements and workflow as contract version 1. "Edit the workflow" under the diagram changes steps, lanes and arrows; confirming again makes version 2. "Edit the wish" under the project name moves the project back to step 1.

From the requirements on, "Documents" shows the requirements document and the project plan (View, download as DOCX or Markdown).

Reload the page at any step: nothing is lost. A wrong or missing key, a rate limit or an invalid answer shows a message and leaves the project where it was.

## First live test with a real key: what to watch

- **OpenAI-compatible provider (D-74), nothing here ran against a real provider**: both the owner's OpenAI and Anthropic accounts had no credit, the Gemini key was only tried by hand (strict `json_schema` answered in 2 s). Unverified in the engine: the strict request through the SDK to Gemini (the SDK adds `"$schema"` to the schema and sends `strict: true`; if Gemini rejects it the JSON-mode retry takes over, and the log of the answer tells which path ran), the Groq and OpenRouter model ids (examples), the JSON-mode retry against a real provider, and the exact 429 wording of Gemini (the retry hint is read from "retry in Ns", `retryDelay` or `Retry-After`). Offline tests use a fake HTTP server on localhost.

- Thinking and max tokens: Sonnet 5.5 thinks by default (adaptive, effort `high`) and thinking counts against `MAX_TOKENS` 20000 (`engine.shared.ClaudeCall`). A "cut off" 502 means raise it or stream. Non-streaming with 300 s timeout: a slow workflow call could time out (504).
- Structured output on this SDK version (3.3.0): the schemas pass the SDK's local validation, but the API's own acceptance is unproven (`ClaudeCall.params`). A 400 with a schema message would show here.
- Error texts: credit exhausted is detected by the 400 text "credit balance" and 402 (`ClaudeCall.problem`); real wording unverified.
- Refusal (422) and `max_tokens` (502) are not retried (`ClaudeCall.answer`).
- The AI check uses `claude-haiku-5-5` (`engine.ai.AnthropicAiConnection`); the model id and no-parameter request are unverified against the live API.
- Prompts and validators (`Anthropic*Writer.SYSTEM_PROMPT`, `*Validator`): real answers may break a limit (8 questions, 40 requirements, workflow shape); the retry sends the reason once.
- Cost of planning calls is not counted anywhere.
- Real runs: keep the machine awake; the first hung step is now killed after 20 minutes of wall time.
