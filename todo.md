## How to test (owner)

**Start** (from the project folder): `ci/run env-up` builds the frontend and the jar, starts PostgreSQL if needed and the engine at **http://localhost:8080**. Stop it with `ci/run env-down`. All checks: `ci/run all-local`.

**With the stub, no key, no cost**: `ENGINE_AI_STUB=true ci/run env-up`. Every Claude answer is then the canteen example (any text you type gives the same brief, 3 questions, 5 requirements and a 6-step workflow); type any text as the key (for example `sk-test`).

**With a real key**: `ci/run env-up` (no `ENGINE_AI_STUB`). Type your Anthropic key into the "Anthropic key" field of the new-project form. It stays in engine memory only; after a restart enter it again. Calls use `claude-sonnet-5-5` and can take up to two minutes each.

**Click path** (the page is `/`; the open project is in the address after `#`, the list is `#projects`, so a reload keeps your place):

0. The start page is "All projects" (open, rename, delete with confirmation). "New project" opens "Describe your idea" (address `#new`).
1. Type the optional name, the wish and the key ("Test" checks the key), "Send to the AI".
2. "Research and ask questions": Claude writes the brief and at most 8 questions; the AI's proposal is preselected on each. Edit, delete or add single questions ("Add a question", "Ask again" replaces all), change answers that do not fit, "Save answers".
3. "Write the requirements with Claude": requirements grouped by epic.
4. "Write the workflow with Claude": swimlane diagram. "Write it again" replaces it.
5. "Review and confirm" shows the counts; "Confirm as contract" freezes wish, brief, answers, requirements and workflow as contract version 1. "Edit the workflow" under the diagram changes steps, lanes and arrows; confirming again makes version 2. "Edit the wish" under the project name moves the project back to step 1.

From the requirements on, "Documents" shows the requirements document and the project plan (View, download as DOCX or Markdown).

Reload the page at any step: nothing is lost. A wrong or missing key, a rate limit or an invalid answer shows a message and leaves the project where it was.

## M4 run (how to test)

Confirm a contract, then press "Run" under the workflow: tasks, steps, cost and console fill live, the ZIP button appears at the end. With `ENGINE_AI_STUB=true ci/run env-up` a run takes seconds and writes small files. Without the stub the engine runs Claude Code per step in a workspace folder (needs the key from the form, or `ENGINE_EXECUTION_USE_SIGN_IN=true` for the machine's sign-in). Cost limit USD 10.

**Live proof of M4 (2026-11-15):** one real run on the canteen contract (stubbed planning, real builder on the machine's Claude Code sign-in, `ENGINE_EXECUTION_REAL_BUILDER=true ENGINE_EXECUTION_USE_SIGN_IN=true`, limit USD 6): 2 software tasks x 4 steps, all green first time, 9.3 minutes, USD 1.52 (`total_cost_usd`), 11 commits; `./check.sh` re-run by hand: CHECK PASSED (25 Vitest, backend tests green). In sign-in mode the session key is not passed to the child (a dummy key gave "Invalid API key" on the first try). Not tried: the real builder with an API key.

## M5 how to test (runs that survive)

All with `ENGINE_AI_STUB=true ci/run env-up`. The stub builder obeys markers written anywhere in the wish (they reach `CONTRACT.md`); type one into the wish of a new project, confirm the contract, press "Run":

| Wish contains | What you see |
|---|---|
| `stub-fail:build:3` | the step "Build with tests" fails 3 times (the first try and 2 fix attempts, "3 attempts" under the step), then the run is "Waiting" with one question: type a hint and "Try again" (or "Skip this step", "Stop the run"); the run continues from the last checkpoint |
| `stub-slow:1500` | every step takes 1.5 s, so there is time to press "Stop the run" (asks for a confirmation, then "Stopped") |
| `stub-crash:build:1` | the run is "Interrupted" after the first step (as after an engine restart); "Continue from the last checkpoint" resumes it (the key field is only needed when the engine has no key) |
| `stub-limit:build:2` | "Waiting for tokens" with the reason and the try number, then the run goes on by itself (waits of 1 minute doubling to 15; `ENGINE_EXECUTION_LIMIT_WAIT_BASE_MS=2000` makes it quick) |

Cost limit: `ENGINE_EXECUTION_COST_LIMIT_USD=0.2` makes a run wait at its limit after one step; the screen asks for a new limit. Settings: `ENGINE_EXECUTION_FIX_ATTEMPTS` (2), `_MAX_RESUMES` (3), `_LIMIT_WAIT_BASE_MS` (60000), `_LIMIT_WAIT_MAX_MS` (900000), `_LIMIT_MAX_RETRIES` (6).

**Live proof of M5 (2026-11-15):** canteen contract (stubbed planning, real builder on the machine's Claude Code sign-in, cost limit USD 3.5), 2 tasks x 4 steps, 9.2 minutes, USD 1.43 (`total_cost_usd`).
